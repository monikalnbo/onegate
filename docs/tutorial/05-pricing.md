# 05 模型价格与计费

不配价格也能用，只是所有成本记 0、额度不扣。想让「用了多少、花了多少」有意义，
就得把价格表填上。这一章讲怎么填、怎么叠加、钱从哪儿扣。

## 5.1 价格表在哪、单位是什么

控制台 →「系统」→「设置」→ 模型价格。

单位是 **每 1M tokens 的价格**（和多数厂商报价口径一致），三个数：

| 字段 | 含义 |
| --- | --- |
| `in` | 输入（prompt）token 单价 |
| `out` | 输出（completion）token 单价 |
| `cache` | 命中缓存的输入 token 单价 |

格式是一个 JSON 对象：

```json
{
  "gpt-4o-mini": { "in": 0.15, "out": 0.6, "cache": 0.075 },
  "gpt-4o":      { "in": 2.5,  "out": 10,  "cache": 1.25 }
}
```

三个字段都必须是非负数字，少一个或写成字符串都会被拒绝（`Invalid pricing for <model>`）。

现在做什么：填入你实际接入的模型名（**必须和客户端请求里的 `model` 完全一致**），保存。

看到什么算成功：保存后不报错；「模型广场」里这个模型的价格列有值。

失败了先查什么：

- 提示 `Invalid pricing for xxx`：这个模型缺 `in`/`out`/`cache` 中的某一个，或值不是数字。
- 模型名对不上：调用记录里 `model` 显示什么，就在这里写什么。

## 5.2 成本是怎么算出来的

单次调用的成本：

```
成本 = 输入tokens × in / 1e6
     + 输出tokens × out / 1e6
     + 缓存tokens × cache / 1e6
```

然后乘倍率，乘哪个倍率取决于密钥类型（看代码里 `billingRates` 的分支）：

| 密钥类型 | 实际计费 |
| --- | --- |
| 独立密钥（管理台建） | 价格 **× 来源倍率 × 密钥组倍率** |
| 门户账户密钥 | 价格 **× 用户组倍率** |

第二条刻意不再乘来源倍率——否则账户会被算两遍。这是设计，不是遗漏。

举例：`gpt-4o-mini` 一次调用输入 1000 token、输出 500 token，
价格 `in=0.15 / out=0.6`：

```
1000 × 0.15 / 1e6 + 500 × 0.6 / 1e6 = 0.00015 + 0.0003 = 0.00045
```

倍率都是 1 时，这条调用成本 0.00045。这个数字会出现在调用记录和使用记录里。

看到什么算成功：调用记录里 `cost` 是非零小数，和你的手算数量级一致。

失败了先查什么：成本是 0 —— 依次确认：价格表有这个模型、倍率不是 0（最小 0.01）、
token 数不是 0。

## 5.3 上游没返回 usage 怎么办

有些上游、有些流式响应不给 `usage`。程序会按文本长度估算：
约 **3.6 个字符 = 1 token**，误差标称 ±20%，记录上带 `estimated: true`。

看到什么算成功：调用记录里的 token 数是估算的，成本照常计算。

失败了先查什么：估算值明显偏大/偏小 —— 这本来就是估算，不要拿它对账；
对账要么让上游返回 `usage`，要么接受误差。

## 5.4 额度：钱从哪儿扣

### 独立密钥：密钥额度

- 建密钥时可以设「额度上限（元）」，`0` 表示不限制。
- 每次调用先从该密钥的额度里扣；`used_usd` 达到 `quota_usd` 后，下一次直接 402 `quota_exceeded`。
- 加额度：密钥列表上的额度操作，填「加多少（美元等值 USD）」，单次需 > 0 且 ≤ 100000。
- 加额度会写审计日志（谁、加了多少、加前加后）。

看到什么算成功：「API 密钥」列表里该密钥的已用/上限数字变化；审计里能看到 `credit key quota`。

失败了先查什么：给账户密钥加额度被拒绝，提示「账户密钥按用户余额结算，请前往用户管理为该账户加额」——
这是对的，去「用户管理」给账户加。

### 门户账户：账户余额

- 用户注册后余额为 0，需要管理员加额或用兑换码充值。
- 管理员在「用户管理」里给账户加额，单次金额 > 0 且 ≤ 100000。
- 账户的计费用「额度单位」记账，具体单位由门户设置里的 `credit_unit_cny` / `credits_per_cny` 决定（见 06 章）。

看到什么算成功：「用户管理」里该用户余额增加，操作日志里有 `credit user` 记录。

失败了先查什么：提示未设置计费单位 —— 先把门户设置的币种与「1 元等于多少额度单位」一起设好，
或者两个都清空。只设一个会被拒绝（`invalid_billing_currency`）。

## 5.5 RPM：限速不是限额度

- 「RPM 限速」= 每分钟请求数，`0` 不限制。
- 超了返回 429 `rate_limit_exceeded`，响应头 `retry-after` 告诉你等几秒。
- 这是按密钥算的，和额度是两回事：额度管「总共能花多少」，RPM 管「一分钟能问几次」。

看到什么算成功：把 RPM 设成 2，快速发三次，第三次拿到 429 + `retry-after`。

失败了先查什么：一直 429 但你没超 —— 检查是不是多个客户端共用同一个密钥。

## 5.6 兑换码（可选）

控制台 →「分销」→「兑换码」→ 新建。填数量（1–200）、金额、备注，生成 `RC-` 开头的码。

用户在门户里兑换，余额增加；码只能使用一次。

看到什么算成功：列表里出现生成的码，`used` 是 false；兑换后变 true 并记录使用者。

失败了先查什么：用户说兑换失败 —— 看这个码是否已被使用、金额是否 > 0。

## 5.7 在线收款（可选，需要商户资质）

控制台 →「客户服务」→「收款设置」。这是易支付风格（MD5 验签）的在线收款，
没有商户号就保持关闭。没配好时门户会明确返回「在线支付尚未开通」，不会假装成功。

需要的字段：启用开关、网关地址、商户号、商户密钥、支付方式、单笔最小/最大金额、每元兑换额度。

> 商户密钥是加密存储的，界面只显示是否已配置，不回显。改任何一项都会让已配置状态失效，
> 需要重新保存完整配置。

看到什么算成功：保存后状态显示可用；门户能拉起支付页。

失败了先查什么：返回 `payment_unavailable` —— 配置没填全或商户密钥解不开；
返回验签失败 —— 商户密钥和支付平台上的不一致。

## 本章验收

- [ ] 你接入的每个模型都在价格表里有三档价格
- [ ] 调一次，调用记录里的 `cost` 非零且量级正确
- [ ] 知道独立密钥和账户密钥各自按什么公式计费
- [ ] 想给某个密钥限额时知道去「API 密钥」加额度，而不是改价格
