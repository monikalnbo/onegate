# 02 首次管理员登录

上一章你已经能让服务跑起来了。这一章只做三件事：打开登录页、登进去、**把管理员密钥换成你自己的**。

## 2.1 登录页在哪

管理台就是同一个服务下的 `/admin/` 路径：

```
http://127.0.0.1:8787/admin/
```

如果你已经在 07 章之前就把 nginx 配好了，那就是：

```
https://admin.example.com/
```

注意结尾的 `/` 要带上。访问 `/admin`（不带斜杠）会被 308 重定向到 `/admin/`，正常。

服务器没有桌面环境时，用 SSH 端口转发在本机浏览器打开：

```bash
ssh -L 8787:127.0.0.1:8787 你的用户名@你的服务器
```

然后本机浏览器访问 `http://127.0.0.1:8787/admin/`。

## 2.2 用什么登录

登录只认一个东西：**管理员密钥**（`RELAY_ADMIN_KEY`），不是用户名密码。

现在做什么：在登录页输入密钥，提交。

看到什么算成功：直接进入控制台，左侧出现「工作台 / 客户服务 / 资源 / 分销 / 数据 / 系统」这几组菜单。

失败了先查什么：

| 现象 | 先查 |
| --- | --- |
| `Invalid admin key`（401） | `.env` 里 `RELAY_ADMIN_KEY` 是否有多余引号、空格、换行；是否改完 `.env` 但没重启服务 |
| `Too many failed login attempts`（429） | 同一 IP 连续错 5 次会锁 5 分钟，等一会或换一个出口 IP |
| 登录成功但页面跳回登录页 | 绝大多数是 Cookie：`COOKIE_SECURE=true` 却在用 HTTP 访问。本地测试改成 `false`，线上用 HTTPS |
| 页面 404 | 地址少了 `/admin/`，或者你用了反向代理但路径前缀没配好（见 07 章） |

> 管理员会话存在内存里，**重启服务后所有人都要重新登录**，这是正常设计，不是故障。

## 2.3 进来第一件事：换掉管理员密钥

管理员密钥等价于 root：谁能登录，谁就能看到并修改全部上游密钥、发新密钥、改价格。
默认密码、示例密码、和别人共享的密码，都必须立刻换掉。

仓库里的做法有两种，**推荐用命令行改 `.env`**，原因见下面。

### 方式 A：命令行改 `.env`（推荐）

```bash
openssl rand -base64 32
sudo -u onegate nano /opt/onegate/.env
# 把 RELAY_ADMIN_KEY= 后面换成刚生成的字符串
sudo systemctl restart onegate
```

看到什么算成功：用新密钥能登录；旧密钥登录返回 401。

### 方式 B：控制台「设置」页轮换

控制台 →「系统」→「设置」，里面有管理密钥轮换表单，要求新密钥至少 12 个字符，需要输入两次确认。

看到什么算成功：提示「管理密钥已更新，下次登录生效」。

> **重要，必须知道的一点：** 控制台轮换只在当前进程内生效，**不会写回 `.env`，也不会写回
> `data/admin.key`**。一旦重启服务，密钥会变回 `.env` 里的那个。
> 所以轮换后请立刻用同样的值更新 `.env` 并重启一次，才算真正生效。
> 这也是为什么更推荐方式 A。

### 关于 `data/admin.key`

`RELAY_ADMIN_KEY` 留空时，首次启动会生成随机密钥写到 `DATA_DIR/admin.key`（权限 0600），
并在终端打印一次 `Relay admin key: ...`。之后每次启动都读这个文件。

它和 `.env` 的关系很简单：**`.env` 里有值就用 `.env` 的，没有才读 `data/admin.key`。**
两边都改容易混乱，建议固定只用一种。

看到什么算成功：`.env` 里是随机长串，`ls -l /opt/onegate/.env` 是 `-rw-------`。

失败了先查什么：改完登录不上——先确认服务真的重启了（`systemctl status onegate`），
再确认改的是实际被读取的那个文件（你用的是 `.env` 还是 `admin.key`）。

## 2.4 先认路：控制台都有什么

左侧菜单对应仓库里真实存在的页面：

| 分组 | 页面 | 用途 |
| --- | --- | --- |
| 工作台 | 仪表盘 | 总览：请求量、成功率、延迟、成本趋势 |
| 工作台 | 调用记录 | 逐条请求账本：状态码、延迟、token、成本、来源 |
| 工作台 | 请求日志 | 最近请求的滚动日志 |
| 客户服务 | 用户信息 / 用户分组 / 用户管理 | 门户账户、用户分组（模型白名单、组倍率）、给账户加额 |
| 客户服务 | 注册邮件 | 邮箱验证服务的 SMTP 配置与验证，见 06 章 |
| 客户服务 | 收款设置 | 在线收款（易支付风格），可选，见 05 章末尾 |
| 资源 | 渠道管理 | 上游来源：地址、密钥、模型、并发、超时、重试、倍率，见 03 章 |
| 资源 | 模型来源 | 按来源分组查看通道健康度 |
| 资源 | API 密钥 | 发密钥、限 RPM、设额度、归组，见 04 章 |
| 资源 | 模型广场 | 模型 × 通道 × 24h 用量 × 价格一览 |
| 资源 | 密钥分组 | 下游密钥分组（模型白名单 + 组倍率） |
| 分销 | 兑换码 | 生成/删除充值兑换码 |
| 分销 | 公告 | 门户公告 |
| 数据 | 使用记录 | 按模型/密钥/状态筛选的使用明细与收入合计 |
| 系统 | 设置 | 模型价格、主题、清理日志、轮换管理员密钥 |
| 系统 | 操作日志 | 最近 200 条审计：谁在什么时候改了什么 |

先点「仪表盘」和「系统 → 操作日志」各看一眼，知道长什么样就行，不用改任何东西。

## 2.5 顺手确认三件事

现在做什么：在「设置」页和「操作日志」页各看一眼。

看到什么算成功：

- 设置页能打开、能看到价格编辑器，说明会话有效。
- 操作日志里能看到你刚才的登录/修改动作（如果做过修改的话）。
- 页面右上角没有报错弹窗。

失败了先查什么：页面空白 + 浏览器控制台报 401，还是 Cookie 问题（HTTPS / `COOKIE_SECURE` 那两个点）。

- [ ] 能打开 `/admin/` 并登录
- [ ] `RELAY_ADMIN_KEY` 已换成随机长字符串，且**写进了会被读取的那个文件**
- [ ] 重启服务后，新密钥仍能登录（验证你真的改对了地方）
